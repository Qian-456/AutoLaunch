## 二、请填写您的创意/想法

### 项目名称
**AutoLaunch：一场发布会，一千种打开方式 —— 让每个人，都能看懂属于自己的那辆车。**

### 我看到的痛点

1. **千人一面**：现在无论线下还是 B 站"云发布会"，用户看到的都是一模一样的 30 分钟线性视频；
   性能党被迫看儿童座椅，奶爸被迫看赛道数据，信息密度被平均拉低。

2. **参数没体感**：发布会念了一堆数字（"587L""800V""300TOPS"），普通人看完没有任何概念；
   很多问题的答案，其实"打开看一眼、切个镜头、指一下"比念 3 页 PPT 更有用。

3. **线下发布成本极高，却没回答用户最具体的问题**：一场中型发布会 50-200 万；
   但用户真正想问的——"零下 10 度冬天续航打几折？""婴儿车能不能竖放？""和 Model S 比充电差多少？"
   发布会一个都没答，事后也搜不到集中整理的答案。

### 我的解法

把一场传统发布会，拆成**三层可组合的模块**：

**第一层 · 可交互 3D 资产层（已有）**
真实可点击的 3D 展车 + 统一动作协议。按钮、点击车模、文字指令、语音、拖拽镜头五种入口，
最终全部归结为同一条 VehicleAction，不维护五套动画路径。
目前 React Three Fiber 端的统一动作协议、动作分发器（幂等/冲突组取消/超时回滚）、
镜头系统、多入口基础层已跑通，本次不造 3D 轮子。

**第二层 · AI Director Agent 编排层（本次核心）**
用户只需要告诉系统"我是谁、我关心什么"（一句话或几个标签），
AI 就从**已注册的章节池、镜头池、动作池**中重新挑选和排序，输出一份只属于这个用户的发布会
脚本计划（结构化 JSON Schema，执行端完全可控），不允许大模型直接操作坐标或未注册动作；
不同人设、不同兴趣点，看到的章节顺序、镜头选择、讲解侧重完全不一样。
本次把时间全部投在 Agent 输出格式的强约束和可回滚验证上。

**第三层 · 产品知识 RAG 讲解层（本次核心）**
把参数表、三电技术、空间实测、竞品对比、车主长测、媒体横评等资料集中向量化；
用户问任何具体问题时，RAG 返回**带引用出处的答案 + 3D 镜头联动动作 + 对比视角 + 追问建议**，
让一句冰冷的数字参数，变成一段"指哪打哪"的体感讲解。
知识库用人工精选 Markdown，不爬全网，同时保留关键词匹配 fallback，断网也能演示。

### 为什么这次 4 小时我能跑通

1. **3D 交互基础层代码已就绪**，本次不写 3D，把时间全部投给 Agent 输出格式和 RAG 问答质量。
2. **Agent 输出强约束 JSON**，只从已注册池中选，执行端一行不改，端到端可控可回滚。
3. **知识库用人工精选 Markdown + 关键词 fallback**，不依赖云端向量化服务，现场断网也能演示。
4. **聚焦"差异化"作为核心亮点**：只要在现场让评委看到"人设 A 和人设 B 的脚本顺序明显不同"
   + "问问题时答案带着镜头一起动"，核心观点就立住了。
